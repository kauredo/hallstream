# Contract between the parts of Hallstream

Four parts are built in parallel from this file. If a part needs something not written here, it adds it here in the same change and says so.

- `internal/…` + `cmd/hallstream` (Go): Bluetooth reader, live state, storage, FPB client, HTTP server.
- `web/overlay/` (HTML/CSS/JS, no build step): the one OBS Browser Source.
- `web/painel/` (HTML/CSS/JS, no build step): the control panel.
- FPB Calendar (Ruby, separate repo): two new endpoints.

`web/` is embedded in the binary with `go:embed`. No framework, no npm, no CDN at runtime: the PC at the club may be offline. Fonts live in `web/fonts/` as woff2 (Graduate, Barlow 400/500/600, Barlow Condensed 500/600/700/800, all OFL).

## Server
- Listens on `127.0.0.1:8765`; if taken, the next free port up to 8775. With `settings.phone_access` on, listens on `0.0.0.0` and every `/api/*` write and `/painel` require the PIN (cookie `pin` or header `X-PIN`); `/overlay` and `GET /api/state` stay open on localhost only.
- On start, opens `http://127.0.0.1:<port>/painel` in the default browser. Before listening it asks each port from 8765 to 8775 for `GET /api/hello`; when one answers as another Hallstream it opens that one's panel and exits. See "App on Windows".
- `GET /` → redirect to `/painel`.
- `GET /overlay` → `web/overlay/index.html`. Query `?screen=<name>` forces a screen (for previews and tests); `?state=<url>` loads state from a JSON file instead of SSE (tests).
- `GET /painel` → `web/painel/index.html`.
- `GET /media/<file>` → files in `dados/media/` (logos, crests, player photos).
- `GET /assets/<file>` → `web/assets/` (embedded): `crest.svg`, `crest.png` (a neutral stand-in shield for the home crest), `hallstream-lockup.svg` (the Hallstream lockup in Soalho, for the panel's dark top bar), `icon/` (the app icon, favicons and `hallstream.ico`, made by `brand/icons.sh`), `pavilhao-demo.jpg` (a synthetic court, the tinted backdrop of the full screens, and the camera stand-in for `?preview=foto`).
- `GET /overlay/<file>` → `web/overlay/<file>` (embedded): `overlay.css`, `overlay.js`, `fixtures/…`. `GET /overlay/` (trailing slash) serves `index.html` too. Added by the overlay: the page links `/overlay/overlay.css`, `/overlay/overlay.js` and `/fonts/fonts.css` by absolute path, because relative links from `/overlay` (no slash) would resolve against `/`.
- `GET /fonts/<file>` → `web/fonts/` (embedded): `fonts.css`, the woff2 files, `OFL.txt`. The panel can link `/fonts/fonts.css` as well.
- `GET /painel/<file>` → `web/painel/<file>` (embedded): `painel.css`, `painel.js`, `mock.js`. `GET /painel/` serves `index.html` too. Added by the panel: it links these by absolute path, for the same reason as the overlay.
- PIN, added by the panel: `GET /painel` (the static HTML) is always served, since it holds no data; the PIN guards `/api/*` and `/api/events`. A request without a valid PIN gets `401 { "error": "…" }`. The panel then shows its PIN screen, sets the cookie `pin=<4 digits>; path=/` and retries. It uses the cookie, not `X-PIN`, because `EventSource` cannot send headers.
- More overlay query params, for tests only: `?preview=1` (dark background behind the transparent page) or `?preview=foto` (the demo hall photo), `?now=<ISO time>` (fixes the clock for the opener countdown), `?anim=0` (no transitions or animations: every element draws in its final state at once, scores without count-up). A forced `?screen=` shows without its entrance.

Rules the Go side owns (the overlay never computes them):
- `game.home/away.name` are the names to show. With no game picked they are the console names (`live.home_name/away_name`). Max 20 characters for the opponent's `name` (12 for `settings.club.name`); `short` max 4. The corner scoreboard shrinks a name down to 16 px and shows `short` instead when it would go smaller (about 17 characters and up); every other screen shrinks the name to fit.
- `away.crest_url` is `null` when there is no logo: the overlay then shows `initials` in the tile. Never the word "Emblema".
- `away.color` is always a colour with white text at ≥ 4.5:1.
- `periods` holds completed periods only, in order. Period N's score is the score at the moment the period value changes from N to N+1, or when the clock reaches 0 in period ≥ 4 and stays there 60 s with no new period. `home`/`away` are that score; `home_points`/`away_points` are the points scored in the period: that score minus the one at the end of the last recorded period (0 before the first), never below 0, so a correction that takes the score under the last period's end gives 0.
- `screen.current` is one of `marcador`, `abertura`, `plantel`, `desconto`, `intervalo`, `final`, `apoiantes`, `proximo`, `voltamos`, `promo`, `nada` (nothing shown). `promo` is only set by `POST /api/promo/:id/show`, never by `POST /api/screen` (see "Promo videos"). `proximo` and `voltamos` are only ever picked by hand (see "Próximo jogo and Voltamos já"). `apoiantes` ("Nossos apoiantes · Juntos pelo clube") shows every sponsor of the game, large; it is only ever picked by hand. With `auto` on: period 2 ends → `intervalo`; the final condition above → `final`; a period ≥ 3 starts after `intervalo` → `marcador`. Manual changes always win until the next automatic trigger. (Go: a period "starts" when its clock first counts down. An overtime that starts after `final` also goes back to `marcador`, since FIBA gives 2 minutes before overtime and `final` fires at 60 s.)
- `lower_third.visible` turns false by itself at `until`.
- `camera` is where the camera picture sits, in overlay px, at full screen (`full`) and on `desconto` (`window`), when the program moves the camera in OBS (see "Time-out squeeze"). `null` when it does not (OBS off, two-scene mode, camera not found yet).
- With `box.connected` false the last live values stay and the overlay shows a small grey dot on the scoreboard. The same dot shows when the program itself stops answering (closed, crashed): 7 s after `/api/events` fails with no state since, until a state arrives again by the stream or by the 2 s poll of `/api/state`.
- Team fouls use 4 pips: pips filled = min(fouls,4), all gold at 4+, the number shows the real count.
- `game.theme` is the overlay's colours, made from `settings.club.primary` and `.secondary` by `club.Theme` (`internal/club`), keyed by CSS custom property name without the `--`. The overlay sets each one on `:root` whenever the state brings a different theme, so a club that changes its colours shows them on air without a reload; a key the theme lacks falls back to the value in `overlay.css`, whose `:root` holds the default club's theme (a test keeps the two equal). `red` is the primary as typed; `kit` (score cells), `blood` (label strips, hard shadows), `ink` (near-black backdrop), `tint` and `tint-dim` (the multiply over the hall photo) are darker shades of it; `red-hi` is the primary lightened to 5.5:1 on `ink` (text on dark grounds), `red-lo` lightened to 5.5:1 on `navy` (small labels), `red-text` darkened to 4.5:1 on white (text on white plates). `navy` is the secondary darkened until white text on it reaches 12:1. `on-red` and `on-kit` are the text on `red` and `kit`: white when it reaches 4.5:1, else whichever of white and `ink` reads better. `red-rgb`, `hi-rgb` and `ink-rgb` are `"r,g,b"` for `rgba()`. The names come from the first look, where the club colour was red and the second navy. The panel's thumbnail and result images (`miniatura.js`, `resultado.js`) draw with the same `game.theme`.
- `game.sport` is `settings.club.sport`; `game.sport_label` is the word the overlay shows next to the club's name (`BASKET`). The labels, by sport: basketball BASQUETEBOL, shown `BASKET`; futsal FUTSAL; handball ANDEBOL; volleyball VOLEIBOL; soccer FUTEBOL. Only basketball can be picked today.
- `game.overlay` is a copy of `settings.overlay`. `bug_position` is `top-left` (default) or `bottom-left`; anything else counts as `top-left`. `sponsor_corner` (default true) and `sponsor_every` (minutes, 1 to 30, default 4) drive the sponsor corner (see "Live touches"). `back_line` is the line under VOLTAMOS JÁ (`""` = none).
- `game.credit` is a copy of `settings.credit` (see "Credit").

How the overlay reads the rest (added by the overlay; Go and the panel should match these):
- `live.period` is a string. `"1"`–`"4"` show as `2º PER.` / `2º PERÍODO`; `"5"` and up are overtime and show as `PROL.` (`PROL. 2` for `"6"`). Anything non-numeric is shown as sent. Go: confirm what the box sends in overtime and map it to `"5"`, `"6"`… here.
- `live.shot` is `""` when the 24 s clock is off; the overlay hides the 24 s box. A value with a decimal point (`"3.2"`) or under 5 turns gold, with one small pulse as it drops under 5.
- Motion (overlay only, nothing for Go to send): screens and the lower third play an entrance when they appear; each screen enters in beats and waits for the previous screen to fade first (except `desconto`, see "Time-out squeeze"); the scoreboard and the time-out screen roll a score that goes up, pop a new foul pip and swap the period label. These live effects never play on the first state after the page loads or after the event stream reconnects, so a reconnect that brings a higher score just shows it.
- `periods[].period` uses the same numbering (5 = first overtime).
- `game.home.crest_url` can be `null` too; both tiles fall back to `initials` the same way. `initials` should always be set (2–4 letters).
- `game.home` comes from `settings.club`: `name` = `name`, `short` and `initials` = `short`, `crest_url` = `crest`, `color` = `primary`. The lockup of the full screens and of the YouTube thumbnail reads "`game.home.name` · `game.sport_label`", and the head of the corner scoreboard "`game.home.short` · `game.sport_label`" (`BASKET` when a state has no `sport_label`).
- `game.start` is ISO 8601 with an offset. The overlay formats it in `Europe/Lisbon`. Up to 12 h before the start the opener says "Começa dentro de 12 min" (or "1 h 20 min") under the time; after the start, and further ahead than 12 h, it shows the date ("Domingo, 15 nov").
- `game.group.coach` empty → the squad hides the Treinador card. `game.group.name` is the title next to PLANTEL. The overlay no longer shows `game.instagram` (the result image in the panel still uses it).
- `game.squad`: the overlay shows the first 12 entries, as cards 7 across in 2 rows; the coach card takes the last two places. With `photos.squad` on, each card has the photo (cropped from the top) with the number and name under it, and the initials when there is no photo; off, the number leads. The panel caps the squad at 12, so 14 places are always enough.
- Sponsor strip: a white strip with thin red dividers at the bottom of `abertura`, `plantel`, `intervalo`, `final`, `proximo` and `voltamos`, under the window on `desconto`, and large on `apoiantes`. It shows every sponsor in one row, the principal first, then `others` in their order, each slot narrower as the list grows. A sponsor with `url: null` (or a logo that fails to load) shows its `name` as text. No sponsors → no strip. The score bug never carries sponsors.
- `game.sponsors` (Go): the principal is the picked escalão's principal, else `geral`'s; `others` are the rest, the escalão's first, then `geral`'s. With no game picked only `geral` counts.
- `lower_third`: `jogador` uses `number`, `first_name` (small, top) and `last_name` (large); `comentador` uses `first_name` + `last_name` (large) and `label` (small, under; empty → "Comentário"). It shows over `marcador` and over `nada`, never over the full-screen graphics. It sits bottom-left under a `top-left` bug and bottom-right under a `bottom-left` one. A change of `bug_position` while the bug shows slides it to the other corner (a fade with reduced motion); the first state just places it.

### Live touches (added by the overlay and Go)
- Score pop: when a team's score goes up by 1 to 3 between two live states, the scoreboard (and the time-out screen) flashes that score cell and rolls the number, and the scoreboard shows a gold plate with "+1", "+2" or "+3" over the home score or under the away score. It pops in over 350 ms on `--ease-pop`, holds 1.2 s and fades over `--t-exit`. A new basket while it shows replaces it. Never on the first state after load or a reconnect, never for a score going down (a correction) or up by more than 3 (a resync). `?anim=0` shows no plate; reduced motion gives a plain fade.
- BÓNUS: with `live.home_fouls` or `live.away_fouls` at 5 or more (FIBA team-foul penalty; overtime counts like any period, whatever the box sends), that team's fouls cell on the scoreboard turns gold and reads "BÓNUS". It goes when the box resets the fouls.
- Period table on `intervalo` and `final`: a row per team, a column per entry of `periods` (`1º`…`4º`, overtime `PROL.`, `PROL. 2`…, as on the scoreboard) with `home_points`/`away_points`, the lower of the two dimmed, and a TOTAL column with the live score. No periods → no table.
- Sponsor corner: a 252x86 white plate top-right on `marcador` (clear of the bug in both positions). With `sponsor_corner` on, every `sponsor_every` minutes after the page loads it shows one sponsor for 10 s with a thin red line that fills, in the strip's order (principal, then `others`), the next one each time. A turn that finds another screen (time-outs and full screens included), a lower third overlapping the corner or no sponsors is skipped; one of them coming up hides the corner. Name instead of logo as in the strip.
- Screenshot params: `?pop=home:3` (or `away:1`…`3`) shows the plate; `?corner=<n>` shows sponsor n in the corner, its line at 62%.
- Credit: with `game.credit` on (or missing, from an older program) the overlay shows the Hallstream lockup (`/assets/hallstream-lockup.svg`, Soalho, letters 22 px tall) on a Marcador backing at 50%, the whole at 80% opacity, bottom-right in the 64 px safe area. It shows only where that corner is free: on `marcador`, `apoiantes` and `promo`. It is hidden on `nada`, on `desconto` (the window and its strip fill the corner) and on the screens with the sponsor strip, and it steps aside while a lower third sits bottom-right (under a `bottom-left` bug). It fades out over `--t-exit` and fades back in over `--t-enter` after `--t-long`, so it never crosses the lower third or the screen before; it only fades, so reduced motion changes nothing.
- `periods` survive a restart: Go writes `dados/periods.json` each time a period is recorded and on a reset, and reads it at start (the demo's own periods are never written; turning the demo off puts the game's periods back). They are cleared by `POST /api/game/reset` and by `PUT /api/game` with another `group_id`, `fpb_game_id` or `start` date (a new time on the same day keeps them). The recording depends on `live.period` changing at the end of each period; check this against the real Stramatel during a game.

## Panel API (JSON unless noted; errors return `{ "error": "mensagem em pt-PT" }` with 4xx)
- `GET /api/settings`, `PUT /api/settings` → `{ "fpb_base_url": "https://calendariofpb.pt", "phone_access": false, "pin": "", "obs": { "enabled": false, "host": "127.0.0.1", "port": 4455, "password": "", "timeout_scene": "", "game_scene": "Jogo", "camera_source": "", "camera_fit": "contain", "camera_full": null, "setup_at": "", "launch": false, "close_on_exit": false }, "start_with_windows": false, "auto_screens": true, "instagram": "", "club": { "name": "CASA", "short": "CAS", "primary": "#2F4B7C", "secondary": "#1C1A17", "crest": "/assets/crest.svg", "sport": "basketball", "country": "PT" }, "club_search": "", "photos": { "squad": false, "lower_third": false }, "overlay": { "bug_position": "top-left", "sponsor_corner": true, "sponsor_every": 4, "back_line": "" }, "credit": true }`. `photos` switches player photos on the squad screen and in the player lower third (both off by default). `overlay.bug_position` ("Posição do marcador" in Definições) is `top-left` or `bottom-left`; `PUT` saves anything else as `top-left`. `overlay.sponsor_corner` (bool, default true) and `overlay.sponsor_every` (minutes, default 4; `PUT` saves anything outside 1 to 30 as 4) are "Patrocinador no canto durante o jogo" in Definições; an older `settings.json` without them gets the defaults. `overlay.back_line` ("Frase do Voltamos já" in Ecrãs, `""` by default) is saved with its spaces collapsed and cut to 60 characters. `credit` (bool, default true) is "Mostrar «feito com Hallstream» na transmissão" in Definições > Grafismo; an older `settings.json` without it loads with it on. It is on by default because the mark is how other clubs find the program; a club that wants a clean picture switches it off.
- `settings.club` is the club profile, in Definições > Clube. `PUT /api/settings` saves `name` with its spaces collapsed, `short` and `country` in capitals, and the colours as `#RRGGBB` (it takes `#rgb` too), and answers 400 with the reason, saving nothing, when `name` is empty or over 12 characters, `short` is empty or over 4, a colour is not `#rgb`/`#rrggbb`, `sport` is not an active sport (only `basketball` today; `futsal`, `handball`, `volleyball` and `soccer` show in the panel as "em breve"), or `country` is not two letters. It never changes `crest` (see `/api/club/crest`). A `settings.json` from before the club profile, with `home_name`/`home_short` and no `club`, gets them as `club.name`/`club.short` (the rest at the defaults) and loses the old keys at the next save. The defaults are a neutral slate blue and the Hallstream ink, both with white text over 8:1.
- `POST /api/club/crest` multipart (`file`, an image up to 10 MB, as the other uploads) saves the crest in `dados/media/club-<id>.<ext>`, makes it `settings.club.crest`, deletes the previous upload and returns the club. `DELETE /api/club/crest` puts back `/assets/crest.svg`, deletes the upload and returns the club.
- The panel offers the FPB (the "Equipas do clube" import and the FPB card in Plantel, "Escolher jogo da FPB" in Jogo, and the FPB fields in Definições > Clube) only while `club.country` is `PT` and `club.sport` is `basketball`. The server side of the FPB (club setup, daily update, `club_search`) is unchanged.
- Age groups: `GET /api/groups`, `POST /api/groups` `{ "name" }`, `PUT /api/groups/:id` `{ "name", "coach", "fpb_team_id" }`, `DELETE /api/groups/:id`.
- Players: `GET /api/groups/:id/players` → `[ { "id", "display_name", "number", "fpb_player_id", "fpb_name" } ]`; `POST` `{ "display_name", "number" }`; `PUT /api/groups/:id/players/:pid` `{ "display_name", "number" }`; `DELETE …/:pid`.
- `POST /api/groups/:id/players/import` → fetches the FPB roster, updates `fpb_name` (and suggests numbers) on linked players, never touches `display_name` or a number the user set. Returns `{ "updated": [player], "suggestions": [ { "fpb_player_id", "name", "number", "games", "best_match": "<local id>|null" } ] }`.
- `POST /api/groups/:id/players/:pid/link` `{ "fpb_player_id", "fpb_name" }`; `DELETE …/:pid/link`.
- `POST /api/groups/:id/players/from-fpb` `{ "fpb_player_id", "name", "number" }` → adds a new local player linked to FPB.
- Sponsors: `GET /api/groups/:id/sponsors` → `[ { "id", "name", "url", "principal" } ]`; `POST` multipart (`file`, `name`); `PUT /api/groups/:id/sponsors` `[ { "id", "principal" } ]` (full order); `DELETE …/:sid`. A setting `shared` group id `geral` holds sponsors used by every age group.
- FPB proxy (cached on disk, so it works offline after one load): `GET /api/fpb/teams?name=` → FPB `/api/teams`; `GET /api/fpb/teams/:id/next-games` → FPB next-games; `GET /api/fpb/teams/:id/roster`.
- Every request to the FPB API (the proxy, the daily update, the next game) goes through one limit, under the calendar's 30 a minute per address: 5 at once, then one every 3 s. A request waits up to 10 s for its turn. After a 429 nothing is sent for the time in `Retry-After` (seconds or a date, 5 minutes at most; 1 minute without the header). A 429, or a turn more than 10 s away, answers with the disk copy and leaves `fpb.reachable` true; with no copy the proxy answers 429 "A FPB está a receber demasiados pedidos. Tente outra vez daqui a um minuto." The updates the program runs by itself (daily, club setup, after a game is picked) take a disk copy served this way as no update: the escalão keeps its `last_sync`, and the daily update stops there until the next day. Photo and logo downloads and the log upload are not counted.
- Game of the day: `GET /api/game`, `PUT /api/game` `{ "group_id", "fpb_game_id", "away": { "name", "short", "color", "crest_url" }, "start", "venue", "competition", "round", "squad": [ { "player_id", "number" } ] }`. When `fpb_game_id` is set and `away.crest_url` empty, the server downloads the opponent logo into `dados/media/` and picks `away.color`. `POST /api/game/opponent-logo` multipart uploads a logo by hand. `POST /api/game/reset` clears periods for a new game.
- The panel reads the game at start and again whenever the game in the live state changes (another device saved it, or the server filled in the FPB crest). With no unsaved edits it takes the new game; with unsaved edits it keeps them and shows "O jogo foi mudado noutro dispositivo" with "Usar o jogo guardado".
- Screens: `POST /api/screen` `{ "screen", "auto" }`. With OBS enabled, `desconto` also squeezes the camera into the time-out window (or, in the two-scene mode, switches OBS to `timeout_scene`), and leaving it undoes that. See "Time-out squeeze".
- Lower third: `POST /api/lower-third` `{ "player_id" }` or `{ "type": "comentador", "first_name", "last_name", "label" }`, optional `"seconds"` (default 8); `DELETE /api/lower-third` hides it.
- Demo: `POST /api/demo` `{ "on": true }` drives `live` with a fake game.

### Próximo jogo and Voltamos já (added by Go, the overlay and the panel)
- `game.next` is the club's game after the one of the day, from FPB next-games of the game's escalão (`fpb_team_id`, 14 days, the disk copy when offline). The game of the day is the entry whose `id` is the game's `fpb_game_id`, and the next game is the earliest entry that starts after it (the FPB's order is not relied on). An entry whose `time` is not "HHhMM" or "HH:MM" can't be placed and is never picked. Without an id, or when the FPB no longer lists it, the game of the day is taken to be on ref's day in Lisbon, ref being `game.start` or, when that is earlier, now less 3 h (a game that runs past midnight); the next game is the first entry on a later day. So a morning setup or a manual game still skips tonight's game.
- `next.at_home` is true when the club is the home side. `opponent` follows the game's rules: `name` from `opponentName`, `short` FPB's `short_name` when it fits in 4 (else the first 3 letters of `name`), `initials` = `short`, the logo from `dados/media/opp-<FPB id>.<ext>` when it is already there, else downloaded to it (`crest_url: null` when that fails) and `color` picked from it at 4.5:1. `full_name` is FPB's name. `start` is RFC 3339 built from FPB `date` + `time` in Europe/Lisbon (Go embeds the zone database for Windows). `venue` is tidied like the game's; `round` is "Jornada N" from `game_week`, else `phase_name`.
- `game.at_home` is the same for the game of the day; `null` when the FPB list has no entry with its id (manual game).
- `game.next` is `null` when there is none, with a short pt-PT reason in `next_note` (no escalão, escalão not linked, team unknown to the FPB, FPB unreachable or answering 429 with no copy, no later game in 14 days, or "A ler os jogos da FPB…" while the game just changed). The panel shows the reason on the disabled "Próximo jogo" button; `POST /api/screen` `{ "screen": "proximo" }` without a next game is refused with 400. The overlay treats `proximo` without `game.next` as `nada`, so it never shows an empty card.
- Go works it out at start and every hour, after each `PUT /api/game`, and after `PUT /api/groups/:id` changes the `fpb_team_id` of the game's escalão, in the background. A result for a game that changed meanwhile is dropped.
- Overlay: both are full screens on the pavilion backdrop with the lockup and the sponsor strip, and follow the full-screen rules: they wait for the previous screen to fade, and a time-out (`desconto`) replaces them like any full screen. `proximo` keeps the club left (`EM CASA` or `FORA` under its name) and the opponent right, with FPB's full name under the short one when they differ; the date reads "SEXTA 20 NOV" and "21:45" in Lisbon. `voltamos` shows the crest, VOLTAMOS JÁ, `back_line` when set, and a small score bar while a game is going on (`box.connected` and a score above 0 or a recorded period). Its only motion while it holds is a slow opacity and scale breath on a halo behind the crest (opacity only with reduced motion, none with `?anim=0`).
- Fixtures: `proximo-casa`, `proximo-fora`, `proximo-longo`, `voltamos`, `voltamos-sem-jogo` (with `?screen=` of the same name).
- Panel "Miniatura YouTube" (Ecrãs) draws a 1280x720 PNG in the browser from the live state (no server call): lockup, `game.group.name`, both crests (initials when one fails to load; images load with CORS so the canvas is never tainted), both names in Barlow Condensed 800, `EM CASA`/`FORA` from `game.at_home` when known, and weekday, date and time from `game.start` in Lisbon. ### Time-out squeeze (added by Go and the overlay)
- One definition: `web/overlay/overlay.css` holds the window (`--win-x: 416px; --win-y: 64px; --win-w: 1440px; --win-h: 810px`, overlay px), its time (`--t-squeeze: 900ms`) and its curve (`--ease-in-out`, a `cubic-bezier`). Go reads these four tokens from the embedded file at start (`readSqueeze` in `internal/web/camera.go`); without them the camera does not move and `POST /api/screen` returns the reason in `obs_error`.
- Settings: `obs.camera_source` is the camera input in the program scene; `""` picks the topmost shown DroidCam input (kind or name contains `droidcam`) below the top browser source, else the topmost shown video capture there (`dshow_input`, `av_capture_input*`, `v4l2_input`, `macos-avcapture`). `obs.camera_fit` is `"contain"` (default; the whole picture, bars where the aspect differs) or `"fill"` (covers the canvas, cropping two sides); it applies to full screen. On `desconto` the picture is always contained in the window, centred; the overlay paints its background around it, with a red frame on the picture. `obs.camera_full` is the last full-screen placement with the source size, canvas size and fit it was made for (`{ "x", "y", "w", "h", "crop_left", "crop_right", "crop_top", "crop_bottom", "source_width", "source_height", "canvas_width", "canvas_height", "fit" }`); only the program writes it, `PUT /api/settings` keeps it, and clears it when `camera_source` changes. Any `camera_fit` other than `"fill"` is saved as `"contain"`.
- Mode: with `obs.timeout_scene` set and present in OBS (`GetSceneList`), the old two-scene switch runs. Otherwise the camera moves in the program scene. New settings default `timeout_scene` to `""`.
- Moving: on `desconto` the server reads the canvas (`GetVideoSettings`), the program scene (`GetCurrentProgramScene`) and its items with their transforms and source sizes (`GetSceneItemList`), then tweens the camera from where it is to the window with `SetSceneItemTransform` every 20 ms over `--t-squeeze` on `--ease-in-out` (top-left alignment, `OBS_BOUNDS_NONE`, crop in whole pixels, scale from what is left). Leaving `desconto` tweens back to the full-screen placement. A new move while one runs starts from the current position, with the time cut in proportion to the distance left, so desconto → marcador → desconto never leaves the camera half way. Automatic screen changes move it too.
- A canvas other than 1920x1080 scales the window by canvas/1920 and canvas/1080 (the overlay is assumed to cover the canvas); `state.camera` stays in overlay px.
- Refit: at start and every 4 s while the screen is `marcador` or `nada`, the server checks the camera; when its source size, the canvas or the fit differs from `camera_full`, it puts the camera at the new full-screen placement at once and saves it.
- `GET /api/obs/sources` (no longer used by the panel, which reads `POST /api/obs/cameras`) → `{ "scene", "sources": [ { "name", "kind" } ], "auto": "<name or empty>" }`, the program scene's inputs from the top; 502 `{ "error" }` when OBS can't be reached.
- `POST /api/obs/camera/fit` ("Ajustar câmara") puts the camera at full screen with the saved fit now, whatever its resolution, and saves it: `{ "ok": true, "fit": { "source", "source_width", "source_height", "canvas_width", "canvas_height" }, "warning": "" }`; `warning` asks for a 1920x1080 canvas when OBS has another. 502 `{ "error" }` when OBS or the camera can't be found. The panel saves the settings form first.
- Errors (OBS closed, source missing, no picture yet) never stop the screen change; `POST /api/screen` returns them in `obs_error` and `GET /api/status` in `obs.error`.
- Overlay: with `state.camera` set, or with `?preview=foto`, `desconto` enters by shrinking the window (and the hole in the background with it) from `camera.full` (else the canvas) to `camera.window` (else the CSS window) over `--t-squeeze` on `--ease-in-out`, in step with the camera; the left column follows as it settles. Leaving, the text fades and the window opens back out on the same curve, then the next screen enters. With neither, the old L-shaped entrance plays. With `?preview=foto` the hall photo plays the camera and moves the same way; without `preview` there is no photo.

### OBS set up by the program (added by Go and the panel)
- `POST /api/obs/setup` `{ "camera": "", "old": "" }` is "Configurar OBS" and "Reparar". One at a time (409 while one runs). It first reaches OBS: with `obs.host` on this PC it reads obs-websocket's `config.json` (`%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json`, OBS 30.2 and later) and uses its port and password when the server is on there. If OBS doesn't answer and `obs64.exe` is not running, it turns the server on in that file (`server_enabled`, `auth_required` true, `server_port` 4455, `first_load` false, a random 24-character `server_password` unless one is there; every other key kept; written through a temporary file and a rename), saves host, port and password in `settings.obs`, starts OBS and waits up to a minute for it. If OBS is running it never writes the file: with the server on in the file it waits up to 20 s (OBS may still be starting), else the step fails and says to close OBS or turn the server on by hand. The check, the write and the start happen under one lock, with the start at launch. A broken `config.json` is never rewritten.
- Then it brings OBS to this state, changing only what differs: scene `Hallstream` (created if missing); the overlay browser source (an input whose `url` path is `/overlay` on a port from 8765 to 8775, preferring the name `Hallstream overlay`, else created with that name) with `url` = the overlay on the port the program runs on, `width` 1920, `height` 1080, `reroute_audio` true, `is_local_file` false, in the scene and shown; the camera in the scene and shown; the overlay above the camera; base and output 1920x1080; the program scene set to `Hallstream` (neither while streaming or recording); then the camera fit of `POST /api/obs/camera/fit`, retried for about 8 s while a new camera has no picture yet. It never deletes or changes a user's source other than the overlay's settings.
- Camera: `camera` is a choice value (`"source:<name>"`, `"device:<video_device_id>"`, `"plugin"`) or `""` for `settings.obs.camera_source` (or automatic when that is empty too). Automatic takes a DroidCam source (kind or name contains `droidcam`, or a `dshow_input` whose `video_device_id` contains it), else a video source already in the scene, else the only choice there is. With several it returns `"result": "choose"` on the camera step and `choices`: video sources in OBS (not browser, image, text, colour, screen or audio kinds), the DroidCam OBS plugin (`droidcam_obs`) when installed with no source yet, and the `dshow_input` devices from `GetInputPropertiesListPropertyItems` (`video_device_id`) that no source uses, DroidCam first. Listing devices needs a `dshow_input`: with none, it adds a hidden one and removes it. A device becomes a new `dshow_input` named after it; the plugin becomes `DroidCam`, connected to the first USB device in its `device_list` (`connect` button). A camera that replaces another hides the old one (`old`, the `camera_source` before the panel saved its form; else the saved one) (and any other capture source) in the scene; it stays in OBS. The camera used is saved as `camera_source`.
- Reply: `{ "ok", "ready", "camera", "steps": [ { "id", "label", "result", "detail" } ], "choices": [ { "value", "type", "label", "droidcam" } ] }`. `result` is `ok`, `created`, `fixed`, `failed`, `choose` or `later` (the canvas size or the program scene can't change while OBS streams or records, so the program leaves them; `later` doesn't count as a problem); step ids are `websocket`, `scene`, `overlay`, `camera`, `old-camera`, `order`, `video`, `program`, `fit`. `ready` (and `ok`) is true when nothing failed but the fit. The first ready run sets `obs.launch` true; every ready run sets `obs.setup_at` and `obs.enabled`. 502 `{ "error" }` when the connection drops half way.
- Health check: the same checks without changes, on every new connection to OBS, every 30 s, and after a setup. `GET /api/status` → `obs.health` `{ "checked", "ready", "problems": [ "<detail of each failed step>" ] }`. With a chosen camera, "missing" means that source is gone.
- `POST /api/obs/cameras` → `{ "cameras": [choice] }` for Definições > Câmara (a POST because listing devices may add and remove a hidden source). 502 when OBS can't be reached.
- Other devices (phones, with the PIN) can run Configurar OBS over the WebSocket but never write `config.json` or start OBS. `GET /api/settings` and `PUT /api/settings` answer them with `obs.password` empty, and their `PUT` keeps `obs.host`, `obs.port`, `obs.password`, `obs.launch` and `obs.close_on_exit` as they are. obs-websocket always listens on every network interface (it has no setting for localhost only), so the password is what guards it.
- Stream: `GET /api/obs/stream` → `{ "known", "stream": null | { "active", "reconnecting", "duration_ms" } }`, kept by the server from `GetStreamStatus` every 3 s while connected (`null` when OBS can't be asked). `POST /api/obs/stream/start` checks `GetStreamServiceSettings` first: an `rtmp_custom` server with an empty `key` → 409 "Configure a conta do YouTube no OBS (Definições > Transmissão) uma vez."; else `StartStream` and the new state. A YouTube account linked in OBS (`rtmp_common`) may keep no key there, so it is not checked; when OBS refuses `StartStream` the 502 says to check the account in OBS. OBS can also take `StartStream` and never send (a linked account with no broadcast shows a message on the PC): when the last `GetStreamStatus` that answered still says not active after 30 s (failed reads in between don't count, and inactive reads are not kept meanwhile, so a stale active status can't end the new broadcast), the program sends `StopStream` and answers 502 telling the operator to look at OBS on the laptop, and a YouTube broadcast made for the start is dropped as for a refusal. `POST /api/obs/stream/stop` → `StopStream`. Already live, or already stopped, is not an error. The program never starts the stream by itself; the panel asks before stopping.
- `obs.launch` ("Abrir o OBS com o Hallstream", Windows): at start, with OBS enabled on this PC and `obs64.exe` not running, the program starts OBS from the `HKLM\SOFTWARE\OBS Studio` install folder (64- then 32-bit registry view), else `%ProgramW6432%`/`%ProgramFiles%\obs-studio`, as `bin\64bit\obs64.exe --minimize-to-tray --disable-shutdown-check` with `bin\64bit` as its working folder (OBS finds its files from there). `--disable-shutdown-check` exists in OBS 30 and 31 only. Then it reconnects with growing waits (1 s to 10 s). It never starts a second OBS.
- `obs.close_on_exit` ("Fechar o OBS ao sair", off by default): "Sair" stops a live stream, then sends `WM_CLOSE` (what the window's X sends) to every top-level window of `obs64.exe`, the hidden tray one too, and waits 15 s; OBS is ended by force after that only when the stream is not live. With the stream live, "Sair" asks first in a message box.
- `start_with_windows` ("Abrir com o Windows", off by default): `POST /api/system/autostart` `{ "on" }` puts `Hallstream.lnk` in the user's Startup folder (made like the desktop shortcut) or removes it, and saves the answer. At every start with the switch on, the program puts the shortcut there again, so a backup unzipped on another PC or a moved exe still opens with Windows. Only from the PC itself (403), 501 where the system has none. `PUT /api/settings` keeps it, and keeps `obs.setup_at`. `GET /api/status` → `"autostart": true` when the switch can show, `"obs_app": true` where the program can start OBS.
- Panel: a stream bar at the top of Ecrãs ("Iniciar transmissão" / "Terminar transmissão", the time on air, "Reparar" when the health check finds a problem), "No ar 0:00:00" in the top bar, and the OBS chip ("Pronto", "Precisa de reparação", "Sem ligação"). Off air, the bar reads "Pronto para transmitir" with a green dot when nothing is missing; otherwise "Fora do ar" and "Antes de começar:" with one line per gap, each linking to the tab that fixes it: the box not connected (unless in demo), no game picked (`group_id` and `away.name` in `GET /api/game`), the OBS health problem or "A verificar o OBS…", and an expired YouTube login. The buttons stay on: the list advises, it doesn't block. Mock states for screenshots: `?mock=1&obs=off|ready|problem|live|nokey|choose`, `&act=setup|start|stop`.

### YouTube (added by Go and the panel)
- The program signs in to the club's channel itself (OBS's own YouTube account can't be driven over obs-websocket). OAuth for installed apps: the club's own "Desktop app" client, a redirect to `http://127.0.0.1:<free port>` on a listener separate from the server, PKCE `S256`, a random `state`, scope `https://www.googleapis.com/auth/youtube`. The listener answers only `GET /` with that Host, ignores a wrong `state` (400, keeps waiting), takes one good answer and closes; it gives up after 5 minutes. `golang.org/x/oauth2` (v0.38.0) does the exchange and the refresh; the API calls are plain REST (`internal/youtube`). Guide for the club: `docs/youtube/SETUP.md` (shipped as `YouTube/LIGAR-YOUTUBE.txt`).
- `dados/youtube.json`: `client_id`, `client_secret`, `token` (refresh token included), `channel`, `stream` (the reusable stream: `id`, `server`, `key`), `expired`. On Windows the whole file is sealed with DPAPI for the Windows user (`DPAPI1:` + `CryptProtectData`, no UI), so another account or a copy of the folder can't read it (a copy needs a new login); elsewhere it is plain JSON at 0600. Temp files (`dados/.tmp-*`) left by a closed program are deleted at start. No endpoint ever returns the secret, the token or the stream key. The login page's text is HTML-escaped.

- PC only (403 otherwise): `PUT /api/youtube/client` `{ "client_id", "client_secret" }` (the id must end in `.apps.googleusercontent.com`; an empty secret keeps the saved one; 409 while connected with another id), `POST /api/youtube/connect` → `{ "auth_url" }` (the panel opens it; a new connect cancels the one waiting), `POST /api/youtube/disconnect` (revokes the refresh token at Google, then forgets token, channel and stream; the client stays).
- After the login: `channels.list mine`, then the stream: a reusable RTMP `liveStream` titled "Hallstream" (found by title in `liveStreams.list mine`, else inserted with `cdn.resolution`/`frameRate` `variable`), and OBS set to `rtmp_custom` with `server` = `ingestionAddress` and `key` = `streamName` (`SetStreamServiceSettings`, only when it differs and OBS isn't live). Configurar OBS does the same as its last step, `youtube` "Transmissão para o YouTube" (`later` while OBS streams). Without YouTube none of this runs and the stream buttons drive OBS as before.
- `POST /api/obs/stream/start` with YouTube connected, before `StartStream`: the game's key (`fpb:<fpb_game_id>`, else `<group>:<date>:<away name>`) finds the last broadcast made for it; when YouTube still has it `created`, `ready`, `testStarting`, `testing`, `liveStarting` or `live`, it is reused (bound again if needed). Otherwise `liveBroadcasts.insert` (`privacyStatus` public, `selfDeclaredMadeForKids` false, `enableAutoStart`/`enableAutoStop` true, `monitorStream.enableMonitorStream` false, `scheduledStartTime` now) and `bind` to the stream. Title: "Casa vs Atlético Vale · Sénior Masculino · 2ª Divisão Masculina J6" (club first at home, opponent first away when `at_home` is false; names from the scoreboard names, words over 3 letters capitalised; "Jornada N" → "JN"); without `<`/`>`, and over 100 characters it drops the competition, then cuts. Description: competition · round · escalão, venue, and the date in Lisbon ("Domingo, 15 de novembro de 2026, 18:00"). An expired login → 409 with "A ligação ao YouTube expirou…", and OBS doesn't start. Body `{ "test": true }` is "Transmissão de teste": 409 without YouTube connected (OBS would send to the public stream); otherwise the same, with `privacyStatus` private, the title prefixed "Teste · " (cut to 100), the key `teste:<key>` so the game's real start never reuses it, and a record with `test` true. The panel sends no thumbnail for it, and at the stop it stays private (no unlist, not picked up by `RunYouTube`; `POST /api/youtube/unlist` answers 409 for it). A test start while the game is on air, or a game start while a test is, is 409, so the record on air keeps its end.
- `GET /api/obs/stream` (and the start/stop replies) add `youtube`: `null` without YouTube, else `{ "connected", "expired", "live": record|null, "ended": record|null, "waiting", "error" }`.
- `POST /api/youtube/thumbnail` multipart (`broadcast_id` of a record, `file`: PNG, 8 MB at most, else 413): the panel draws the Miniatura YouTube canvas after a start whose `live.thumbnail_set` is false and sends it; the server calls `thumbnails.set`. A 403 (channel not verified for custom thumbnails) → 502 with a message; the stream goes on. Behind the write guard as the fourth multipart upload.
- Stop (`POST /api/obs/stream/stop`, or OBS reporting the stream off): the record on air gets `ended`, `score` and `result` ("Casa 82-76 Atlético Vale"). Then, in the background: a look at the broadcast 30 s later, then 1, 2, 4, 5, 5… minutes apart, 10 looks at most; at `complete`, `videos.list` + `videos.update part=status` with `privacyStatus` unlisted and `embeddable`, `license` and `publicStatsViewable` sent back as they were (YouTube clears status fields left out). Still `live` at the fourth look → one `transition` to `complete`. Never live → `privacy_error` says so. Out of looks → `privacy_error` asks for "Tornar não listado" later. ### Game logs (added by Go)
- `dados/timeline.jsonl`: one JSON line per change the video-stats side can't get from `raw.log`, each with `ts` (RFC 3339, milliseconds, local offset) and `event`: `stream_start` and `stream_stop` (`broadcast_id`, `""` without YouTube; `test`), `screen` (`name`; `auto` true when the program switched it: the automatic rules, or a promo clip that ended by itself), `lower_third` (`shown`, `type`, `number`; never names), `box` (`connected`), `game` (`key` as in "YouTube", `""` with no game picked; `home`, `away`; written when one of them changes, and at start), `period` (`period`, `home`, `away`, when a period is recorded; periods restored at start are not written again). Right after `stream_start` come `game`, `screen`, `lower_third` and `box` as they are then, each with `initial: true`. `stream_stop` carries the time the batch's cut ends at. Nothing is written while the demo runs (the initial `game` line excepted). Score and clock stay in `raw.log`.
- After each stream stops (Terminar, or OBS stopping by itself, test streams included) the program writes a batch to `dados/envios/<batch>/` and sends it to `settings.fpb_base_url` + `/api/marcador/logs` (`POST`, `Authorization: Bearer <token>`, the FPB client's `User-Agent`, multipart). The token only goes over https to `calendariofpb.pt` or a subdomain, redirects included; with `fpb_base_url` pointing elsewhere (`PUT /api/settings` takes it from a phone with the PIN too) nothing is sent, the batch stays pending and `marcador.log` says why once. `batch` is `<broadcast id>-<YYYYMMDD-HHMMSS>` (the stream's start, so two streams on one reused broadcast stay apart) when the id starts with a letter or digit and has only letters, digits, `.`, `_` and `-`, or `local-<YYYYMMDD-HHMMSS>` otherwise; `meta` is `meta.json`; each file is a `files[]` part named `raw.log.gz`, `timeline.jsonl.gz`, `marcador.log.gz`, `marcador.log.1.gz` (when there is one) and `bluetooth.log.gz`, all gzipped.
  - Every file holds only the lines from 30 minutes before the stream started to its end. The start is when OBS says the stream began, or the broadcast's `started_at` when that is earlier and at most 6 hours before it (a broadcast still on air across a restart of the program); it is never more than 6 hours before the end. `started_at` starts again when an ended broadcast is reused, and is cleared when OBS refuses to start. In `raw.log`, `timeline.jsonl` and `bluetooth.log` a line without a readable time is left out; in `marcador.log` (and `.1`) it goes with the line before it.
  - `marcador.log` with the Windows user's folder (any case, `\` or `/`) written as `~`, the bare user name as `(utilizador)`, any other `X:\Users\<name>` as `~`, and every player's name (`display_name`, `fpb_name`) as `(jogador)`: whole words, in any case, with or without accents. `bluetooth.log` only with the lines of likely boxes (`likely=true`): the rest are the phones and earphones of people in the hall.
  - Limits (the server's): at most 10 MB a gzipped file, 10 files and 25 MB a request (413 over that). A batch that would pass them keeps only the newest lines of `raw.log` that fit.
  - `meta`: `{ "version", "broadcast_id", "video_id", "title", "test", "escalao", "opponent", "stream_start", "stream_end" (RFC 3339 with offset), "score": { "home", "away" }, "box_address", "box_name" }`, plus `"truncated": true` when `raw.log` was cut to fit. Without a broadcast, `title` is the one the broadcast would have had and `escalao`/`opponent` come from the live game. Never the PIN, the OBS password, the YouTube client secret or any token.
  - A 200 deletes the batch. 401, 404, 429 and 5xx leave it for the next round. Any other 4xx (400, 413) is not retried: the batch moves to `dados/envios/falhados/` and the reason goes in `marcador.log`. Either way the round goes on to the newer batches; no network ends it. Errors are logged once until the next 200. Pending batches are tried oldest first at start and every 10 minutes. A batch with the name of one still waiting replaces it. `falhados` keeps the newest 20 batches; a batch pending for more than 60 days moves there, with a line in `marcador.log`.
  - The token comes from the build (`-X main.uploadToken=$HALLSTREAM_UPLOAD_TOKEN` in `build.sh`). Without it the program writes no batch, sends nothing and says so once in `marcador.log`.
  - `GET /api/status` → `uploads`: `pending` (batches waiting), `last_ok` (RFC 3339 of the last 200 since start, `""` before), `last_error` (`""` after a 200). The panel shows nothing new.

### App on Windows (added by Go)
- The exes are `Hallstream.exe` (amd64) and `Hallstream (32-bit).exe` (386), built with `-H windowsgui`, so no console window. They carry the icon (`web/assets/icon/hallstream.ico`), a manifest (Windows 10, per-monitor DPI v2, common controls v6) and version info (ProductName and FileDescription "Hallstream", CompanyName "Clube Exemplo", OriginalFilename the exe's name, version from `./build.sh <version>`). `build.sh` makes `cmd/hallstream/rsrc_windows_{amd64,386}.syso` from `winres/winres.json` and `winres/winres-386.json` with go-winres (v0.3.3, a `tool` in go.mod) before each build and deletes them after; they are not committed. `brand/icons.sh` rebuilds every icon file from `brand/icon.svg` (40 px and up) and `brand/icon-16.svg` (16 to 32 px).
- Messages go to `dados/marcador.log` (and the console where there is one, on macOS and Linux). At 1 MB it becomes `marcador.log.1` and a new file starts. An error that stops the start (data folder, server) shows in a message box on Windows; elsewhere on the console, waiting for Enter.
- Tray icon by the Windows clock, tooltip "Hallstream". Left click opens the panel. Menu: "Abrir painel", "Copiar endereço do overlay", a grey status line ("Caixa: ligada", "Caixa: à procura", "Caixa: Bluetooth desligado", "Modo demonstração"), "Sair". "Sair" (and Windows logging off) finishes a camera tween at its target, lets go of the box, waits for a settings or game save in progress, closes the log and exits. On other systems there is no icon; Ctrl+C does the same clean-up.
- One at a time: a second start finds the first through `GET /api/hello` → `{ "app": "hallstream", "version" }`, opens its panel and exits. When 8765 is held by another program, the server takes the next free port as before and a message box tells the volunteer the new overlay address for OBS.
- `GET /favicon.ico` → the app icon (`image/x-icon`); the overlay page gets its tab icon from it. `/assets/icon/` holds `favicon.svg`, `favicon-32.png`, `apple-touch-icon.png` (180), `icon-192.png` and `icon-512.png` (full-bleed, the shield inside the centre 80% for Android masks) and `hallstream.ico`. `GET /painel/manifest.webmanifest` (`application/manifest+json`): name "Hallstream", short_name "Hallstream", start_url `/painel`, display standalone, theme `#BD1522`, background `#8E101B`, every URL absolute so it works the same from a phone on the LAN. None of these need the PIN.
- Desktop shortcut. `settings.desktop_shortcut` is `""` (not asked yet), `"created"` or `"declined"`; only the server changes it (`PUT /api/settings` keeps it). `GET /api/status` also returns `"shortcut": true` when this system can make one (Windows) and the request comes from the PC itself, and `"data_dir"` (the `dados` folder). With `shortcut` true and `desktop_shortcut` empty the panel asks above the tabs ("Criar" / "Agora não"); Definições has a "Criar atalho no ambiente de trabalho" button whenever `shortcut` is true.
- `POST /api/system/desktop-shortcut` `{ "create": true }` puts `Hallstream.lnk` on the user's Desktop (the real folder, OneDrive included), pointing at the running exe, started in its folder, with its icon, replacing one already there; saves `desktop_shortcut: "created"` and returns `{ "ok": true, "path" }`. `{ "create": false }` saves `"declined"`. `501 { "error" }` when the system has no shortcut (not Windows), `500 { "error" }` when it fails. Behind the write guard like every write.

## Data folder (`dados/`, next to the .exe)
- `settings.json`, `groups.json` (groups with players and sponsor metadata), `game.json` (current game), `media/` (uploaded and downloaded images), `cache/fpb/*.json`, `jogos/<YYYY-MM-DD>-<group>.json` (history: game info, periods, final score), `raw.log` (every box frame, as now), `bluetooth.log` (devices heard while scanning), `marcador.log` (+ `marcador.log.1`, the program's messages), `score/*.txt` (the old text files, kept for existing OBS setups), `promo.json` and `promo/` (club videos, see "Promo videos"), `youtube.json` (the YouTube login, served only inside the backup below) and `transmissoes.json` (the streams), see "YouTube". `timeline.jsonl` and `envios/` (the game logs waiting to be sent, and `envios/falhados/`), see "Game logs".
- Writes are atomic (write temp, rename).
- Backup ("Guardar cópia", Definições > Cópia de segurança, shown only on the PC): `GET /api/system/backup` streams a zip named `Hallstream-copia-<YYYY-MM-DD>.zip` holding the whole folder under `dados/`, minus `raw.log*` (it grows all season) and `.tmp-*` files. Videos and pictures are stored, the rest deflated. A file deleted during the walk is skipped; any other error is logged and cuts the connection, so the browser shows a failed download. Only from the PC itself (403, also for a request another site sends, by `Sec-Fetch-Site`), since it holds the OBS password and the YouTube login. Restoring is by hand: with the program closed, unzip it into the program's folder. Ajuda > "Passar para outro computador" and the LEIA-ME give the steps.

## FPB Calendar endpoints (separate repo)
- `GET /api/teams?name=` (already there) → `[ { "id", "name", "age": "Sub 14", "gender": "Feminino", "slug", "squad_label": "Sub 14 F", "url", "has_fixtures" } ]`, current season only. Every request sends `User-Agent: hallstream/<version>` (Cloudflare blocks Go's default).
- `GET /api/teams/:id/next-games?days=14` → `{ "team": { "id", "name", "short_name", "logo_url" }, "games": [ { "id", "date": "2026-11-15", "time": "18H00", "location", "competition_name", "competition_slug", "game_week", "phase_name", "home": { "id", "name", "short_name", "logo_url" }, "away": { … } } ] }`, today and the next `days` days (max 60), sorted by date and time. `logo_url` falls back to `club_logo_url`.
- `GET /api/teams/:id/roster` → `{ "team": { "id", "name" }, "season", "players": [ { "player_id", "fpb_athlete_id", "name", "slug", "jersey_number", "photo_url", "games" } ] }`. `photo_url` is the FPB photo (`https://sav2.fpb.pt/uploads/…`) or `null`; older deploys without `fpb_athlete_id`/`photo_url` still decode (zero values): players with a `game_player_stats` row for this team in the team's season; `jersey_number` from their most recent game; sorted by jersey number.
- Both: 404 JSON for an unknown team, `Cache-Control: public, max-age=300`, inside the existing `api/ip` throttle.
